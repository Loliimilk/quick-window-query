# QwQ – Quick Window Query

**QwQ** – экспериментальное приложение для выделения области экрана, распознавания текста и работы с языковыми заметками. Проект также развивается как исследовательская платформа для изучения методов OCR, предварительной обработки изображений и последующего языкового анализа.

> **Статус:** ранний прототип. Отдельные компоненты работают, но полный пользовательский сценарий от захвата изображения до отображения распознанного текста в интерфейсе пока не завершён.

## О проекте

QwQ задуман как инструмент, который позволит получать текст непосредственно с экрана, анализировать его и сохранять полезные языковые материалы. Помимо разработки приложения, отдельное направление проекта – исследование того, как свойства изображения и методы его обработки влияют на качество оптического распознавания символов (OCR).

Основные направления работы:

- выделение произвольной области экрана и получение изображения;
- распознавание текста с помощью OCR;
- исследование и сравнение методов предварительной обработки изображений;
- разработка и проверка адаптивных подходов к улучшению качества распознавания;
- интеграция с языковыми моделями (LLM) для перевода и грамматического анализа;
- организация языковых заметок и сохранение результатов работы.

Наличие направления в этом списке **не означает**, что оно уже реализовано: текущее состояние описано ниже.

## Текущее состояние

**Реализовано в прототипе:**

- оверлей для выделения области экрана на PyQt5;
- передача координат выделенной области в Go-компонент;
- захват области экрана и отправка PNG в отдельный OCR-сервис;
- OCR-сервис на базе FastAPI и EasyOCR;
- веб-интерфейс с демонстрационными фразами;
- локальное хранение заметок и настроек в `localStorage` браузера.

**Пока не реализовано или не объединено в единый сценарий:**

- передача распознанного текста из OCR в веб-интерфейс;
- полноценный пользовательский сценарий «выделить → распознать → проанализировать»;
- готовая интеграция с LLM в рамках описанного здесь прототипа;
- экспериментальная платформа с опубликованными сравнительными результатами.

## Архитектура

Текущая цепочка обработки изображения:

```text
PyQt5 overlay
    │ выделенная область (координаты)
    ▼
Go backend                         POST :8080/update-bounds
    │ захват экрана → PNG
    ▼
FastAPI + EasyOCR                 POST :8001/binary
    │ распознанный текст
    ▼
Вывод в консоль Go
```

Веб-интерфейс пока работает отдельно от OCR. Для демонстрации он использует данные из `frontend/src/pages/capture/phrase.json`. Заметки и настройки сохраняются в `localStorage` браузера.

### Структура репозитория

| Путь | Назначение |

## Установка и запуск

### Требования

Для сборки и запуска текущего прототипа под **Windows** понадобятся:

- **Go** – локальная разработка проверялась на версии **1.26.5**; совместимость с более ранними версиями не подтверждена;
- **Node.js и npm** – версия Node.js должна соответствовать требованиям используемого Vite (см. зависимости проекта);
- **Python** – с поддержкой устанавливаемых версий PyQt5, PyTorch и EasyOCR;
- доступ к интернету при установке зависимостей и, возможно, при первом запуске EasyOCR для загрузки моделей.

В OCR сейчас включено `gpu=True`. Для работы через GPU нужна подходящая сборка PyTorch и совместимое оборудование. Если такого окружения нет, может потребоваться изменение конфигурации OCR на `gpu=False`.

### Подготовка окружения

Откройте **PowerShell** в корне репозитория и выполните команды по порядку.

Создайте виртуальное окружение Python:

```powershell
python -m venv .venv
```

Установите Python-зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Установите зависимости интерфейса:

```powershell
Push-Location frontend
npm ci
Pop-Location
```

Загрузите Go-зависимости:

```powershell
go -C backend mod download
```

Корневой `requirements.txt` включает зависимости для оверлея и OCR-сервиса. Версии Python-пакетов заданы диапазонами, поэтому установка пока не полностью воспроизводима: отдельного lock-файла для Python нет.

### Автоматический запуск

Из корня проекта:

```powershell
.\start.bat
```

Скрипт использует каталог проекта как рабочую директорию, запускает OCR-сервис и Go-компонент, ожидает доступности порта Go, после чего запускает оверлей и Vite. Откройте адрес, который Vite покажет в терминале.

> При первом запуске EasyOCR может загружать модели. Пока сервис не готов, Go может выводить ошибки подключения.

Для остановки завершите процессы в открытых окнах с помощью **Ctrl+C** и закройте окна. Если запуск прервался, уже запущенные компоненты следует остановить перед повторной попыткой.

### Раздельный запуск

Если нужно запустить компоненты вручную, откройте **четыре терминала** в корне репозитория и выполните по одной команде в каждом.

**Терминал 1 — OCR-сервис:**

```powershell
.\.venv\Scripts\python.exe -m uvicorn ocr_server:app --app-dir ocr_service --port 8001
```

**Терминал 2 — Go backend:**

```powershell
go run ./backend/cmd/app
```

**Терминал 3 — оверлей:**

```powershell
.\.venv\Scripts\python.exe overlay/main.py
```

**Терминал 4 — веб-интерфейс:**

```powershell
npm --prefix frontend run dev
```

## Исследовательское направление

Одна из целей QwQ – использовать приложение как основу для воспроизводимых экспериментов по качеству OCR.

**Планируемые направления исследований:**

- влияние шума, размытия, масштаба, сжатия и контраста на распознавание;
- распознавание текста на сложном фоне, включая полупрозрачные элементы;
- сравнение фильтрации, бинаризации и других методов предобработки;
- оценка методов обработки одного кадра и последовательности кадров;
- выбор обработки на основе характеристик входного изображения;
- сравнение качества распознавания и вычислительных затрат, включая задержку.

Для оценки результатов предполагается использовать наборы изображений с эталонным текстом, метрики ошибок распознавания (например, **CER**) и показатели производительности.

Планируется отделить автоматизированные проверки программы (`tests/`) от научных экспериментов (`experiments/`) и сравнительных наборов (`benchmarks/`). **Эти каталоги описывают предполагаемую организацию дальнейшей работы и не обязательно присутствуют в текущей версии.**

В будущих публикациях экспериментов предполагается указывать исходные данные, настройки алгоритмов обработки, методику измерений и полученные результаты, чтобы их можно было проверить независимо.

## Языковые модели

Интеграция LLM рассматривается как отдельное направление развития QwQ: восстановление смысла распознанного текста, перевод, грамматический анализ и формирование языковых заметок.

Проект не содержит в этом README готовых рецептов подбора моделей, промптов и параметров генерации. При самостоятельной интеграции языковой модели разработчик отвечает за её настройку и формат взаимодействия с приложением.

**Текущий публичный прототип не следует считать готовым LLM-клиентом:** работающий сквозной сценарий с LLM здесь пока не заявлен.

## Ограничения

- Основной документированный сценарий запуска рассчитан на Windows.
- OCR пока выводится в консоль Go, а не в интерфейс.
- Интерфейс использует демонстрационные фразы.
- Набор зависимостей Python не зафиксирован lock-файлом.
- Первый запуск OCR может потребовать загрузки моделей.
- Работа OCR с GPU зависит от конфигурации PyTorch и оборудования.
- Архитектура и API могут изменяться без сохранения обратной совместимости на этапе прототипа.

## Участие в разработке

Предложения по улучшению, сообщения об ошибках и обсуждения исследовательских подходов приветствуются через Issues. Перед крупными изменениями желательно сначала обсудить идею.
